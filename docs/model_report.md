# 延迟风险模型报告

## 业务问题

在订单发出或支付确认时，能否根据已有信息判断订单是否可能延迟送达？

## 标签

- `late_flag = 1`：实际送达时间晚于预计送达时间；
- `late_flag = 0`：实际送达时间不晚于预计送达时间；
- 未送达或缺少时间字段的订单不参与训练。

## 输入特征

- 商品金额；
- 运费；
- 订单商品数量；
- 商品平均重量；
- 买卖双方地区；
- 是否跨州；
- 预计配送天数；
- 下单月份；
- 支付方式。

## 模型

第一版使用 Logistic Regression 作为可解释基线模型。项目代码同时支持 Random Forest，以便比较线性模型和非线性模型。

## 评估指标

- Accuracy：整体分类准确率；
- Precision：预测为高风险的订单中，真正延迟的比例；
- Recall：实际延迟订单中被识别出来的比例；
- F1：Precision 和 Recall 的综合指标；
- ROC-AUC：模型区分正常订单和延迟订单的能力。

## 面试重点

1. 业务上更关注 Recall，因为漏掉高风险延迟订单可能影响用户体验；
2. 不能把实际送达时间和评价分数作为特征，否则会产生数据泄漏；
3. 模型输出风险概率后，还需要结合卖家、地区和品类分析，才能转化为业务动作。
