# Codex 辅助开发记录

本项目使用 Codex 按照“先设计、再测试、后实现、最后验证”的方式完成，重点保留可复现的工程过程，而不是只生成一次性代码。

## 开发流程

1. 根据岗位 JD 提取 SQL、Python、指标体系、机器学习、AI 应用和 A/B 测试能力要求；
2. 将项目拆分为数据管道、指标层、分析服务、机器学习、AI 编排和展示层；
3. 先编写行为测试，验证数据可重复生成、KPI 口径、模型防泄漏和 AI 意图护栏；
4. 逐步实现最小可行版本；
5. 使用演示数据验证完整链路，再支持真实 Olist 数据；
6. 通过测试、AST 语法检查和 Streamlit 启动验证；
7. 进行代码审查，修复边界条件和可复现性问题。

## 可展示的 Codex 使用能力

- 能将自然语言需求拆解为模块化架构；
- 能要求 AI 先写测试，再实现功能；
- 能让 AI 生成数据字典、指标口径和面试演示脚本；
- 能通过测试结果而不是“看起来能运行”判断代码质量；
- 能审查并修复 AI 生成代码中的数据泄漏、异常输入和权限边界问题。

## 复现命令

```powershell
$env:PYTHONPATH = "$PWD\src"
python scripts\generate_demo_data.py
python scripts\build_warehouse.py
python -m pytest -q -p no:cacheprovider
streamlit run app.py
```

## 面试表达建议

不要只说“这是 Codex 帮我写的项目”。更好的表达是：

> 我使用 Codex 辅助完成需求拆解、测试用例设计和代码审查，但我自己负责业务口径、数据建模、模型特征选择、AI 护栏和最终验证。项目所有核心模块都可以本地复现，并通过自动化测试。
